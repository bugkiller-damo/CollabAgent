## 2. Phase 0 — 数据模型与基础类型

### 2.1 数据库扩展

**新表 11 张：**

| 表名 | 用途 | 关键字段 |
|---|---|---|
| `assets` | 资产清单 | ip, hostname, os, ports, services, asset_level, tags |
| `penetration_tasks` | 渗透任务 | status(8态), priority(4级), targets(JSON), checkpoints, findings |
| `penetration_results` | 渗透结果 | cvss_score, severity, vuln_type, attack_path, exploit_evidence |
| `attack_graphs` | 攻击图 | nodes, edges, version(版本化) |
| `cases` | 病例库 | status(5态), cvss_score, vuln_type, distribution_status, affected_fingerprints |
| `alert_rules` | 告警规则 | metric, condition(JSON), channels, notify_interval_min |
| `alerts` | 告警记录 | status(3态), source, trace_id |
| `adapters` | 适配器注册 | type, provider, auth_config, health_status |
| `audit_logs` | 审计日志 | actor_id, action, target_type, target_id |
| `roles` | RBAC 角色 | name, is_system |
| `role_permissions` | 角色权限 | role_id, resource, action, scope |

**预置 6 个系统角色**（已播种）：
- `system_admin` / `security_analyst` / `pen_tester` / `approval_admin` / `auditor` / `subsidiary_admin`

## 3. Phase 1 — 通信协议增强

### 3.1 新增模块

| 文件 | 功能 | 关键参数 |
|---|---|---|
| `ws/presence.ts` | 在线状态管理 | 30s 心跳超时 / 15s 清理周期 / 3 态(online/offline/busy) |
| `ws/offline-queue.ts` | 离线消息缓存 | 7 天过期 / 4 级退避重试(LOW→CRITICAL) / 智能去重 |
| `lib/alert-engine.ts` | 后台告警评估 | 30s 评估周期 / 采集 4 个指标 / 触发时自动落库 |

### 3.2 现有 handler.ts 增强

- `presenceManager` 全局实例（带 status_change 自动广播）
- `offlineQueue` 全局实例（ACK 自动清除）
- 新增 `sendWithAck(userId, message)` 内部 API（HIGH/CRITICAL 自动入队兜底）
- 兼容所有现有导出（`wsHandler` / `daemonClients` / `daemonMeta` / `broadcast` / `broadcastToDaemons` / `setWsPg`）

### 3.3 新增 WS 消息类型

| 消息类型 | 方向 | 说明 |
|---|---|---|
| `heartbeat` / `heartbeat_ack` | 双向 | 心跳保活 |
| `ack` | 双向 | 消息确认（`content.ack_message_id`） |
| `status_change` | 双向 | 在线状态变更广播 |

## 4. Phase 2 — 安全业务模块（v1 API）

### 4.1 路由总览

所有 v1 路由统一挂载在 `/api/v1/*`，共 28 个端点。

### 4.2 资产管理

| 方法 | 路径 | 功能 |
|---|---|---|
| `POST` | `/api/v1/assets` | 创建/upsert 资产（`UNIQUE(subsidiary_id, ip)`） |
| `GET` | `/api/v1/assets` | 列表（subsidiaryId/assetLevel/status/tags/q 过滤 + 分页） |
| `GET` | `/api/v1/assets/:id` | 详情 |
| `PATCH` | `/api/v1/assets/:id` | 部分更新 |
| `POST` | `/api/v1/assets/import` | 批量导入（≤1000 条） |

### 4.3 渗透任务管理

| 方法 | 路径 | 功能 |
|---|---|---|
| `POST` | `/api/v1/tasks` | 创建任务（`idempotencyKey` 幂等） |
| `GET` | `/api/v1/tasks` | 列表（多维过滤 + 排序） |
| `GET` | `/api/v1/tasks/:id` | 详情 |
| `GET` | `/api/v1/tasks/:id/status` | 状态+进度+漏洞统计 |
| `POST` | `/api/v1/tasks/:id/control` | 控制（pause/resume/stop/terminate）含 8 态状态机 |
| `GET` | `/api/v1/tasks/:id/results` | 结果（含分页漏洞列表） |
| `GET` | `/api/v1/tasks/:id/attack-graph` | 攻击图（支持 `since` 增量） |
| `GET` | `/api/v1/tasks/:id/logs` | 智能体日志时间线 |
| `POST` | `/api/v1/tasks/:id/msg` | 发送消息给智能体 |
| `POST` | `/api/v1/tasks/batch` | 批量创建/控制（≤50 项） |

**状态机（已验证）：**

```
pending ──(engine接单)──→ queued ──→ running ──→ completed
                          │            │  │
                          │  pause  ←──┘  └─→ paused ──resume─→ running
                          │                                │
                          └──→ (cancel/terminate) ←────────┘
```

### 4.4 病例库

| 方法 | 路径 | 功能 |
|---|---|---|
| `POST` | `/api/v1/cases` | 上报病例（自动 `pending_review`） |
| `GET` | `/api/v1/cases` | 检索（q/severity/vulnType/cveId/tag/status + 排序） |
| `GET` | `/api/v1/cases/:id` | 详情 |
| `PUT` | `/api/v1/cases/:id/status` | 状态机：approve/reject/archive/revise/mark_fixed |
| `POST` | `/api/v1/cases/:id/feedback` | 修复反馈（fixed/partial/not_applicable/fix_failed） |
| `GET` | `/api/v1/cases/notifications` | 分发通知拉取（30 天内已发布） |

**状态机（已验证）：**

```
pending_review ──approve──→ published ──archive──→ archived
                ──reject───→ rejected
published ──revise──→ pending_review（可重新审核）
```

### 4.5 告警规则

| 方法 | 路径 | 功能 |
|---|---|---|
| `POST` | `/api/v1/alerts/rules` | 创建规则（含 condition JSON） |
| `GET` | `/api/v1/alerts/rules` | 规则列表（subsidiaryId/enabled 过滤） |
| `PUT` | `/api/v1/alerts/rules/:id` | 更新规则 |
| `DELETE` | `/api/v1/alerts/rules/:id` | 删除规则 |
| `GET` | `/api/v1/alerts/history` | 告警历史（多维过滤 + 分页） |
| `GET` | `/api/v1/alerts/stats` | 统计（按 severity/status 聚合） |
| `POST` | `/api/v1/alerts/:id/acknowledge` | 确认告警 |

**AlertEngine 采集指标：**
- `memory.heapUsedMb` / `memory.heapTotalMb` / `memory.rssMb`
- `tasks.running` / `tasks.failed_last_hour`
- `alerts.recent_5min`

### 7.3 P2 — 中期（3-4 周）

#### 7.3.1 OAuth 2.0 完整实现

- `POST /api/v1/oauth/token` — Client Credentials + Auth Code+PKCE
- 服务间 token 缓存与自动刷新
- 移除 dev-token 兜底

#### 7.3.2 双平面通信

- 新增 `lib/api-direct.ts` — 服务间 HTTP 直连
- 关键数据（策略下发/病例同步）通过 API 直连确保可靠
- 冲突检测：按消息 ID 逐条比对，序列号高者覆盖

#### 7.3.3 Daemon 适配新协议

`packages/daemon/src/core.ts` 升级支持：
- `heartbeat` 主动发送（每 15s）
- `ack` 消息自动回复
- `policy_publish` 处理
- `status_change` 监听并联动本地 agent 状态

### 7.4 P3 — 长期（1-2 月）

- **多实例水平扩展**：Redis（限流 + pub/sub 广播）
- **指标持久化**：环形缓冲 + Prometheus 接入
- **容器化部署**：修 compose、添加环境变量必填校验、cookie Secure 标记
- **审计日志完整性**：SHA-256 哈希链、只读快照
- **离线数据缓存**：子公司离线时本地 SQLite 缓存，网络恢复后回放
