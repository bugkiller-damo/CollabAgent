## 一、Agent 接入向导（一键化 / 可视化）

面向新使用者的入驻链路：注册 → 一行命令接入本机 Claude → 创建 Agent → 协作。

- **新增接入向导页 `/connect`**（`ConnectWizard.tsx`）+ 侧栏入口。三步式、按真实状态推进：
  1. **连接本机 Claude**：生成机器令牌 → 渲染可一键复制的本地接入命令 → 轮询 `/api/daemon/status` 实时检测 daemon 是否连上。
  2. **创建 Agent**：daemon 在线后填名字/模型创建（已连接的 daemon 会自动接管新 Agent）。
  3. **开始协作**：轮询检测新 Agent 上线，给出进入频道入口。
- 接入命令采用**本地 monorepo 形式**：`pnpm --filter @collabagent/daemon dev -- --server-url <origin> --api-key <token>`（npm 包未发布前的过渡形态）。
- `POST /api/auth/machine-token` 适配：缺省 `serverId` 时自动落到用户个人组织，向导可零参数调用。
- daemon 启动**预检 claude CLI**（`core.ts checkClaude` 复用 `probeClaude`）：缺失时打印清晰中文安装/登录指引，不阻断启动。

## 二、修复：Agent 在线状态 + WS 机器令牌解析（之前是“假在线”）

- `/api/agents` 的 `isOnline` 原为 `daemonClients.size > 0`（任一 daemon 在线则全员显示在线）。查明 `daemonClients` 以 **userId** 为键（一台机器一个 daemon），改为 `daemonClients.has(a.user_id)`，`agents.ts` 同源两处一并修正。
- **根因 bug**：WS 握手只做 `jwt.verify`，而 daemon 用 `sk_machine_` 令牌（非 JWT）→ 验证失败 → 所有 daemon 被登记成 `"anon"`，导致上面的 `has(user_id)` 永远不命中。修复：`ws/handler.ts` 改为异步解析——机器令牌走 bcrypt 比对 `machine_tokens` 拿真实 userId，浏览器走 JWT。
- 新增 `GET /api/daemon/status`（按当前用户判断其 daemon 是否在线，向导第 1 步用）。
- `AgentManagement` 页加 5 秒轮询，daemon 上线/下线无需手动刷新即可见。

## 三、修复：claude 探测误判 + Vite `/ws` 代理

- **claude 探测 EINVAL**：`probeClaude` 找到 `claude.cmd` 后用 `execFileSync` 不带 `shell` 执行 `.cmd`，Node 18+ 抛 `EINVAL` → 本机明明装了 claude 也被判为“未检测到”。修复：对 `.cmd/.bat` 包装器用 `shell:true` + 引号包裹路径（兼容含空格目录）。实测正确识别 `2.1.159 (Claude Code)`。
- **Vite `/ws` 未代理**：`vite.config.ts` 只代理了 `/ws/chat`（浏览器用），daemon 连的 `/ws` 没代理 → 向导生成的命令（指向 5173）WS 握手失败。补 `/ws` 代理（排在 `/ws/chat` 之后避免前缀吞并）。实测经 Vite 代理后 Authorization 头正确透传、后端成功登记 daemon。
