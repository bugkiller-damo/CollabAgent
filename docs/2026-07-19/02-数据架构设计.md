> 版本：2026-07-19 · 以当前代码实现为准（`packages/server/src/db/`、`packages/daemon/src/`）

## 1. 存储总览

系统采用"一个主存储 + 多层辅助存储"的结构：

| 层 | 技术 | 内容 | 位置 |
|----|------|------|------|
| 主存储 | PostgreSQL（postgres.js 驱动） | 全部业务数据：账号、组织、频道、消息、智能体、任务、提醒、指标 | `DATABASE_URL` 指向的实例 |
| 内存缓存 | 进程内 Map + TTL | session 有效性（5s）、频道访问（2s）、默认 server id（60s） | server 进程 |
| 限流后端 | Redis（可选）或进程内存 | 限流计数器 `INCR`+`PEXPIRE` | `REDIS_URL` 设置时启用 |
| 附件存储 | 本地磁盘 | 上传文件字节流 | `<cwd>/uploads/`，经 `/files/` 提供下载 |
| Daemon 本地态 | 文件系统（JSON + 文本） | run 记录、agent 工作区、终端日志、wrapper、重启标记 | daemon 进程的 `.slock/` |

连接池：`max = DB_POOL_MAX`（默认 10）、`idle_timeout 30s`、`max_lifetime 1800s`。事务经 `pg.transaction()`（包装 `sql.begin()`）使用。

迁移由 `db/migrate.ts` 引导时执行：跟踪表 `_migrations(name PK, applied_at)`，按文件名顺序应用 `migrations/*.sql`，全部迁移幂等。

## 4. ER 关系

```
users ─┬─< servers (created_by)            servers ─┬─< agents
       ├─< user_sessions (FK cascade)               ├─< channels
       ├─< machine_tokens                           ├─< machine_tokens
       ├─< agents (user_id, 归属)                   └─< invites
       └─< notifications (FK cascade)
channels ─┬─< messages ─┬─< message_reactions (cascade)
          │             ├─< message_edits (cascade)
          │             ├─< message_attachments >── attachments
          │             └─< messages (thread_id 自引用)
          ├─< channel_members (cascade, 多态 member_id)
          ├─< action_cards
          └─< dispatches (from/to → agents)
agents ─┬─1:1 agent_credentials
        └─< agent_logins >── integrations
reminders ─< reminder_events (cascade)
```

**多态无外键列（有意设计）**：`channel_members.member_id`、`messages.sender_id`、`message_reactions.user_id`、`attachments.uploader_id`、`reminders.owner_id`、`action_cards.created_by`。这些列需要在 human/agent 两种实体间多态引用，放弃数据库级 FK 换取单表多态，一致性由应用层（路由校验 + ON DELETE 应用级清理）保证。

## 5. 索引与查询设计

| 查询路径 | 支撑索引 |
|----------|----------|
| 频道消息倒序分页 | `idx_messages_channel_seq (channel_id, seq)`，`seq DESC LIMIT n+1` 判 hasMore |
| 增量拉新消息（agent receive） | `idx_messages_server_seq (server_id, seq)` + `agents.last_seen_seq` 游标 |
| 全文检索 | `idx_messages_content_tsv GIN`（生成列，simple 配置）；可选 jieba 中文分词索引。**注意：需求规格 §4.2.6 明文要求中文检索禁用 `simple`、须用 pg_jieba/zhparser**——当前 simple 为主索引（对中文按整词切分，质量有限），003 迁移已提供 pg_jieba 索引但未默认启用，属与规格的已知冲突。**另注意双轨制**：人端搜索（messages.ts）走 `content_tsv`，agent 搜索（agents-messages.ts）仍用表达式 `to_tsvector('simple', content)` 命中旧索引 `idx_messages_search`——agent 路径切换到生成列后旧索引可删除 |
| 线程回复 | `idx_messages_thread` 部分索引 |
| 任务板 | `idx_messages_task_status` 部分索引（仅任务行） |
| 到期提醒扫描 | `idx_reminders_status_fire (status, fire_at) WHERE status='scheduled'` |
| 未读通知计数 | `idx_notifications_unread` 部分索引 |
| 每频道单经理 | `idx_channel_members_single_manager` 部分唯一索引 |
| token 认证 | `token_hash UNIQUE`（sha256，O(1)；bcrypt 历史行全表比对兜底） |
| handle/name 大小写不敏感唯一 | `lower(...)` 表达式唯一索引（users/agents/channels） |

分页约定：消息类接口以 `seq` 为游标（`before`/`after`/`around` + `limit` 默认 50）。

## 6. 缓存与失效

| 缓存 | 位置 | TTL | 失效 |
|------|------|-----|------|
| session 有效性 | `lib/session-check.ts` Map | 5s | `clearSessionCache()`：logout / logout-all / session 吊销 / 改密 / 注销 |
| 频道访问/角色 | `lib/access.ts` | 2s（10s 周期清扫） | 自然过期 |
| 默认 server id | `lib/server.ts` | 60s | 自然过期 |
| 限流计数 | Redis 或内存 | 60s 窗口 | 窗口过期；Redis 故障时 fail-open |

指标：`metrics_samples` 每 60s 采样一次，调度器保留 7 天。

## 7. 附件与文件存储

- 上传：`POST /api/attachments/upload`（multipart，`MAX_UPLOAD_SIZE` 默认 10MB，MIME 白名单 `ALLOWED_MIME_TYPES`）→ `storage_key = <randomUUID>/<原始文件名>` → 字节写入 `<cwd>/uploads/`，元数据入 `attachments`。
- 下载分层鉴权：`/files/` 静态 scope 仅要求登录（authenticate）；`GET /api/attachments/:id` 做细粒度校验（上传者本人或所挂消息频道成员，`?meta=1` 只取元数据）。
- 路径安全：`resolve().startsWith(baseDir)` 防路径穿越；URL 编码的 key 解码后仍在基目录内才放行。

## 8. Daemon 本地持久化（`.slock/`）

daemon 进程 cwd 下的纯文件存储（无数据库）：

| 路径 | 写入者 | 内容 |
|------|--------|------|
| `daemon-state.json` | `agent-run-store.ts` | `{runs: AgentRunRecord[], states: AgentRuntimeState[]}`，`.tmp`+rename 原子写 |
| `planned-restart` | `supervisor.ts` / `daemon-core.ts` | 计划内重启标记（含时间戳）；下次启动消费并删除，用于区分崩溃与计划停止 |
| `sysprompt-<safe>.md` | `agent-startup.ts` | 每 agent 生成的系统提示（源文件） |
| `workspaces/<safe>/` | `agent-startup.ts` | agent 专属工作区；首次创建播种 `MEMORY.md` 模板（角色/关于用户/频道与长期任务/近期上下文） |
| `workspaces/<safe>/CLAUDE.md` | `agent-runtime-spawn.ts` | 每次 spawn 写入，Claude Code 按 cwd 自动加载 |
| `workspaces/<safe>/.mcp.json` | 同上 | slock MCP server 配置（env 传 SLOCK_AGENT_ID/TOKEN/SERVER_URL） |
| `workspaces/<safe>/.claude/settings.local.json` | 同上 | `enableAllProjectMcpServers: true` |
| `terminal-logs/<safe>.log` | `terminal-log.ts` | 每次 run 结束落盘的终端画面（纯文本）；单文件 >512KB 截断保留尾部 256KB |
| `slock.bat` / `slock` / `slock.cmd` | `setup-slock-wrapper.ts` / `claude-setup.ts` | CLI wrapper（cmd + POSIX sh 双格式，注入 SLOCK_* 环境变量） |
| `slock-cli.cjs` | 同上 | esbuild 预打包 CLI（失败回退 `npx tsx`） |
| `slock-mcp-server.cjs` | `mcp-bundle.ts` | esbuild 打包的 MCP server 单文件 |

**目录命名**：`safeAgentDirName(name)` — 纯 `[a-zA-Z0-9_-]` 原样使用；含非 ASCII 字符时清洗为 `_` 并追加 6 位 base36 码点哈希（防等长中文名坍缩为同一 `_____` 目录）。`legacyAgentDirName` 仅用于定位并迁移旧目录。

**daemon-state.json 两种记录**：

- `AgentRunRecord { runId, agentId, agentName, status: starting|running|exited|error, exitCode, startedAt, endedAt, messagesProcessed, lastTurnDuration }`
- `AgentRuntimeState { agentId, agentName, status: uninit|idle|starting|working|stopped, lastTransitionAt, totalRuns, currentRunId, lastSessionId, lastSessionUpdatedAt }`（`lastSessionId` 供崩溃恢复时 `claude --resume`）

启动时 `markUnfinishedRunsStale()` 把遗留 starting/running 记为 error（autostart 候选采集必须先于此调用，见《智能体协作体系详细设计》§5）。

## 9. 数据安全

| 项 | 机制 |
|----|------|
| 密码 | bcrypt（改密 cost 12） |
| 高熵 token（machine/agent） | sha256 落库 + 唯一索引 O(1) 验证；历史 bcrypt 行兼容逐行比对 |
| 会话吊销 | JWT `sid` + `user_sessions.revoked_at` + `users.token_version` 双重校验（5s 缓存） |
| CSRF | 双提交（`csrf_token` 可读 cookie vs `X-CSRF-Token` 头）；Bearer 凭证豁免 |
| 软删 | 用户 `deactivated_at`、提醒 `status='canceled'`、消息删除置空 content |
| 级联 | channels/messages/reminders 删除级联清理子表（FK ON DELETE CASCADE 或事务内逐表删） |
| 凭证生命周期 | agent scoped token 24h TTL，重签即撤旧；mint/revoke 端点要求账号级 machine token（防自我续期） |

## 10. 已知限制与演进方向

1. **消息表无保留策略**：messages 只增不减，长期需分区/归档。
2. **run store 仍是 JSON 文件**：`agent-run-store.ts` 已抽象 `IAgentRunStore` 接口，Phase 5 计划迁移 SQLite。
3. **drizzle 未决**：`db/schema.ts` 是 Drizzle 风格的 TS 镜像，但查询层仍为手写 SQL，是否全面引入 ORM 未定。
4. **metrics 无降采样**：7 天 × 每分钟一行，长期趋势需要降采样表或外部时序库。
5. **多态列无 FK**：一致性依赖应用层，数据修复成本高；如规模扩大可考虑拆表。
6. **附件仅存本地磁盘**：多实例部署需切换对象存储（`lib/storage.ts` 已按接口隔离）。
7. **无消息队列层**：规格 §4.2.6 要求 Kafka/Redis Streams + 持久化库两级存储；当前为 PostgreSQL 单级 + WS 直发，无消息回放/削峰能力（单实例规模下可接受）。
8. **多 daemon / 托管化的数据层影响**：agents 表需增加部署模式/归属字段，可能新增 daemons 注册表——见 `05-演进规划.md` E3。
9. **`::text` 强转废索引**（ecc postgres 审查 2026-07-19）：`lib/orgs.ts` 的 `user_id::text = $1`（我的组织查询，且 server_members.user_id 无前导索引）与 `agents-public.ts` 的 `server_id::text = ANY($1)`（idx_agents_server_name 前导列本可用）——UUID 与字符串参数比较时的强转使索引失效。当前表小无感，建索引/改参数类型时应一并消除强转。
10. **提醒索引近重叠**：`idx_reminders_due (status, fire_at)` 与部分索引 `idx_reminders_status_fire` 有重叠，但前者还服务 status='fired' 查询，保留两者可辩护。
