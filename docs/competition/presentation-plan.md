# 广石杯汇报 PPT 制作计划（10 分钟 + ≤3 分钟视频）

> 依据 `docs/报名表-AI Agent 原生协作平台.xlsx` 申报口径制定，对应五个评分维度：
> 1. 参赛项目必要性与重要性
> 2. 原型的功能、技术实现质量与创新性（需现场运行原型演示）
> 3. 团队实力及研究基础
> 4. 实施计划及预期成效
> 5. 推广潜力与风险控制

## 一、整体时间分配（10 分钟）

| 段落 | 时长 | 对应评分维度 |
|------|------|--------------|
| 1. 必要性与重要性 | 2:00 | 维度 1 |
| 2. 功能演示与创新性 | 4:00（含 ≤3:00 视频） | 维度 2 |
| 3. 团队实力与研究基础 | 1:00 | 维度 3 |
| 4. 实施计划与预期成效 | 1:30 | 维度 4 |

PPT 共 **13 页**，讲解节奏约 45 秒/页。

## 二、PPT 逐页结构

**P1 封面**（15 秒）
- 标题：AI Agent 原生协作平台 —— 让 AI 智能体成为团队成员
- 单位：中冶京诚数字科技（北京）有限公司 · 智慧城市部；赛道：应用原型赛 / 管理协同

**P2 痛点：三个断层**（45 秒）⭐维度 1 核心
- AI 是工具不是成员：上下文随对话丢失，跨 3 个 AI 工具的任务人工串联 5 次以上
- 任务协同断裂：Jira/Trello 与 AI 聊天互不互通，每任务多花 15 分钟切换
- 知识无法沉淀：团队每周浪费 3-4 小时重复 AI 对话
- 建议配一张"现状 vs 本平台"对比示意图

**P3 目标用户与必要性**（30 秒）
- 用户：企业研发团队、项目管理团队、跨部门协作小组
- 一句话立意：**把 AI 从"被@的工具"变成"持久在线的团队成员"**

**P4 方案概览：业务闭环**（45 秒）
- 一张闭环图：人类发布需求 → AI 分析建议 → 任务自动创建 → AI 执行汇报 → 人类审查 → 知识归档
- 承上启下，说完直接进视频

**P5 演示视频**（≤3 分钟，见第三部分分镜）

**P6 技术架构：四层架构**（45 秒）⭐维度 2
- 服务端（Node.js + PG + Valkey）/ 本地守护进程 / AI 运行时（隔离子进程）/ Vue 3 前端
- 强调：敏感数据不出企业网，AI 子进程无网络权限

**P7 三大技术创新点**（45 秒）⭐维度 2 核心
1. Agent 原生通道协议（MCP 扩展，8 种运行时热插拔）
2. 门控消息投递（AI 思考期缓冲、空闲窗口精准投递）
3. 持久化团队记忆（跨会话上下文恢复）

**P8 团队与牵头单位**（60 秒）⭐维度 3
- 中冶京诚：冶金工程数字化龙头背景，智慧城市部有真实落地场景
- 团队 5 人分工：陈郅（架构/申报）、郭梦娟、韩昱、沈明宇、许延平 —— 需补每人一句话职责
- 研究基础：已完成 daemon 全量重构、频道经理派发、多 Agent 所有权隔离等里程碑

**P9 实施计划**（45 秒）⭐维度 4
- 三阶段：原型完善（当前）→ 部门试点 → 公司级推广
- 需补具体时间线（建议按季度，从 2026 Q3 起）

**P10 预期成效**（45 秒）⭐维度 4
- 效率 +40-60%、沟通成本 -50%、任务遗漏率 -80%、新人上手 3 天→半天
- 建议加"试点验证方式"一句话，让数字显得可考核

**P11 推广潜力**（45 秒）⭐维度 5
- 路径：智慧城市部 → 中冶京诚各事业部 → 工程行业 → 通用企业研发团队
- 资源需求低：小型团队 1 台服务器即可；支持本地化部署

**P12 风险与应对**（45 秒）⭐维度 5
- 数据安全 → 本地 daemon 架构 + 双层令牌认证
- 模型依赖 → 8 种运行时热插拔，不绑定单一供应商
- 多 Agent 冲突 → 原子认领 + 所有权隔离

**P13 结尾**（15 秒）
- 一句话收束 + 致谢页

## 三、演示视频分镜（2 分 50 秒，录屏 + 旁白字幕）

> 原则：**一条故事线走完业务闭环**，不堆砌功能。真人需求驱动，AI 是"成员"的感觉要演出来。

| 时间 | 画面 | 要点 |
|------|------|------|
| 0:00–0:20 | 团队频道界面，人类成员发一条需求消息（如"给登录页加验证码"） | 展示频道内人 + AI 成员共存 |
| 0:20–0:50 | AI（架构师角色）自动感知上下文，回复分析建议；需求一键转为任务卡片 | 体现"主动感知"而非被@才响应 |
| 0:50–1:30 | 频道经理派发任务给前端开发 Agent；任务看板「待办→进行中」自动流转 | 体现任务协同不断裂 |
| 1:30–2:10 | 开发 Agent 在任务线程中实时汇报进度（流式输出 + 工具调用），完成后「审查中」；人类确认 →「完成」 | 体现 AI 执行 + 人类把关 |
| 2:10–2:35 | 新成员/AI 重新加入频道，自动载入历史决策上下文，直接引用之前的结论回答追问 | 体现知识沉淀（差异化最强的一幕） |
| 2:35–2:50 | 快速闪过：多 AI 运行时切换、终端观察、门控投递缓冲提示 | 一句话带过技术深度，收束 |

录制要点：
- 提前把演示路径跑稳并**录屏备份**，现场放视频而非 live demo（报名表要求"现场运行原型"，建议视频为主、现场准备一个可点的静态环境兜底）
- 控制消息间隔，用门控投递的"缓冲→投递"视觉反馈作为记忆点
- 全程加字幕，旁白可后期配
